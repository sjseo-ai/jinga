부동산 가치평가 + 주식·환율 인텔리전스 단일 페이지 웹앱과, 실시간 데이터를 공급하는 Cloudflare Worker 프록시 모음입니다.

## 1. 폴더 구조

| 경로 | 내용 |
|---|---|
| `site/public/index.html` | 메인 사이트 전체(HTML+CSS+JS 단일 파일). 현재 배포본과 100% 동일 |
| `site/wrangler.toml` | 사이트 배포 설정(Workers + Static Assets) |
| `workers/jinga-yahoo-proxy/` | 지수·종목·환율 시세 프록시 (네이버 우선 + 야후 대체) |
| `workers/jinga-korea-macro/` | 기준금리·주간지수·주담대금리·실거래가 프록시 |
| `workers/jinga-policy-proxy/` | 부동산 정책 뉴스 프록시 (Google 뉴스 RSS) |
| `workers/jinga-realestate-proxy/` | (미사용) 실거래가 단독 프록시 — 아래 5번 참고 |
| `legacy/` | 병합 이전 초기 버전 2종 (배포 안 됨, 참고용) |

## 2. VS Code에서 바로 시작하기

```bash
npm install                 # wrangler 설치
npx wrangler login          # 브라우저로 Cloudflare 로그인 (최초 1회)

npm run deploy:site         # 사이트 배포
npm run deploy:macro        # 거시지표/실거래가 Worker 배포
npm run deploy:quotes       # 시세 Worker 배포
npm run deploy:policy       # 정책뉴스 Worker 배포
npm run deploy:all          # 전부
npm run check               # Worker 3종 문법 검사
```

대시보드의 Quick Edit 편집기가 불안정할 때가 있어서, **앞으로는 wrangler CLI 배포를 권장**합니다. 같은 Worker에 배포되며 결과도 동일합니다.

로컬 테스트는 `npm run dev:site` 또는 `npm run dev:macro`로 하면 되고, Worker를 로컬에서 돌릴 때 필요한 키는 `.dev.vars` 파일에 넣습니다(`.gitignore`에 이미 포함).

**지역 지도 = KB시세 구·동 집계 (2026-09-11 변경)** — 국토부 실거래 API 키가 거부(403)되는 동안 지역 지도·법정동 순위를 KB시세로 채웁니다.
- `npm run kb:gu`(`scripts/build-kb-gu.mjs`) → `site/public/kb-seoul-gu.json`. 서울 50세대 이상 아파트 약 4,400곳의 주택형별 KB 일반거래가를 전용 평당가로 환산해 세대수 가중평균(구·법정동별), 직전 집계(다른 KB 기준일) 대비 변동률 포함. 약 3분.
- KB가 요청이 몰리면 일시 거부하므로 동시 3건 + 건별 재시도 + 실패분 순차 재조회. 80% 미만 성공이면 기존 파일을 덮지 않음.
- 매주 월요일 작업(`weekly-report.bat`)이 보고서보다 먼저 실행. 배포 사이트에는 파일이 정적 자산이라 **재배포해야** 반영됨.
- 국토부 키가 해결되면 `/trade/apt`(실거래)도 다시 쓸 수 있으나, 현재 페이지는 KB 집계만 읽음.

**주간 보고서 메일 구독 (2026-09-14 추가)** — 사이트의 「보고서 구독」에서 누구나 신청 → 확인 메일 링크 클릭 → 매주 월요일 보고서 메일.
- 신청·확인·해지: Vercel 함수 `site/public/api/`(subscribe·confirm·unsubscribe, 운영 PC용 admin). 구독자는 비공개 Vercel Blob 스토어 `jinga-subscribers`에 `subs/<id>.json`으로 저장.
- 발송: 이 PC가 **Gmail(앱 비밀번호) 또는 네이버 메일**(smtp.naver.com:465 — 메일 환경설정의 IMAP/SMTP 사용 켜기, 2단계 인증 시 애플리케이션 비밀번호)로 보냄. 주소 도메인으로 자동 판별.
  설정 `.scriptsmail-setup.cmd` → `.secrets/jinga-mail.json`(`provider`·`senderUser`·`senderPass`·`smtpAuthUser`, git·배포 제외). 서버 발송 전환(2026-09-15) 뒤로는 같은 값을 Vercel 암호화 환경변수에도 넣음(`npm run vercel:env`) — 아래 「서버 주간 발송」. 예전 `gmailUser`·`gmailAppPassword` 키도 읽음.
  - 확인 메일: 작업 스케줄러 「진가 구독 확인메일」이 10분마다 `scripts/mail-confirm.bat`(기록 `reports/mail.log`). 7일 미확인 신청은 삭제.
  - 주간 메일: `weekly-report.bat` 4단계 `send-weekly-mail.mjs` — 받는 사람마다 한 통, **그 구독자 조건으로 만든** 보고서 HTML 본문 + 엑셀 첨부 + 조건 바꾸기·수신 거부 링크(List-Unsubscribe 헤더). `npm run mail:test`로 본인에게 시험 발송(본인이 구독자면 본인 조건 보고서).
- 관리 키: Vercel 환경변수 `JINGA_ADMIN_SECRET`(production) = `.secrets/jinga-mail.json`의 `adminSecret`. 바꾸면 둘 다 바꿀 것.
- 개인정보: 수집 항목 메일 주소·보고서 조건, 목적 조건별 주간 보고서 발송, 보유 구독 해지 시 즉시 삭제(동의 체크 필수, 동의 시각 `consentAt` 기록). 스토어 지역은 iad1(미국).

  - 이용약관 제4조를 「지식재산권과 산식 공개」로 바꿔 같은 원칙을 명시 — 읽고 검증은 환영, 무단 복제·배포·상업적 이용은 금지.
- 배포본 빌드(`scripts/build-site.mjs`, `npm run build:site`) — 소스(`site/public`)는 그대로 두고 **올리는 사본(`site/.build`)에만** 손댐.
  - `index.html`·`admin.html` 의 **인라인 `<script>`** 만 압축(약 39KB 감소) — 화면을 잇는 배선이고, 데이터 출처를 적어 둔 개발 메모가 공개 페이지에 남지 않게 하려는 것. 산식은 여기에 없음.
  - HTML 마크업·CSS 는 건드리지 않음(공백 하나에 배치가 달라질 수 있어서). `src=` 로 불러오는 것과 JSON-LD 는 제외.
  - 여러 `<script>` 가 전역 변수를 함께 쓰는데, esbuild 는 **모듈이 아닌 코드의 최상위 이름을 바꾸지 않아** 그대로 이어짐(모듈은 자기 범위라 안전). 결과에 `</script` 가 들어가면 태그가 끊기므로 escape.
  - `scripts/deploy-vercel.mjs` 가 올리기 전에 이 빌드를 돌리고 `site/.build` 를 배포.
  - `.vercel`(프로젝트 연결 파일)은 **반드시 사본에 포함** — 빼면 Vercel 이 폴더 이름으로 새 프로젝트를 만들어 사이트가 통째로 다른 주소에 하나 더 생김(실제로 한 번 겪음).

## 4. 남은 작업 — 실거래가(MOLIT) 키 문제

### 상황
- data.go.kr "국토교통부_아파트 매매 실거래가 자료" **활용신청 승인 완료**(2026-08-21 신청, 개발계정, 2028-08-21 만료) — 마이페이지에서 확인함
- 그런데 API 호출 시 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR / 등록되지 않은 서비스키`(403)
- Cloudflare에 등록된 `MOLIT_API_KEY` 길이가 **96자** → data.go.kr의 **Encoding 키** 형태로 추정

### 원인
data.go.kr은 같은 키를 두 가지로 제공합니다.

| 종류 | 형태 | 길이 |
|---|---|---|
| 일반 인증키 (Decoding) | `+`, `/`, `==` 가 그대로 | 보통 88자 안팎 |
| 일반 인증키 (Encoding) | `%2B`, `%2F`, `%3D` 로 변환됨 | 92~100자 |

기존 배포본은 받은 키를 URL용으로 한 번 더 인코딩하기 때문에, Encoding 키를 넣으면 `%` → `%25`로 **이중 인코딩**되어 다른 키가 됩니다.

### 해결 — 둘 중 하나
**(a) 키만 교체** — 지금 배포된 코드로 바로 동작
```bash
npx wrangler secret put MOLIT_API_KEY --config workers/jinga-korea-macro/wrangler.toml
# 프롬프트에 "일반 인증키 (Decoding)" 값을 붙여넣기
```

**(b) 이 저장소의 최신 코드 배포** — 어느 형태를 넣어도 동작
```bash
npm run deploy:macro
```
`workers/jinga-korea-macro/src/index.js`에는 아래가 이미 반영되어 있고, **아직 배포되지 않은 유일한 변경분**입니다.
- `molitKey()` — 이미 퍼센트 인코딩된 키는 그대로, 아니면 인코딩
- 403 응답 시 키 인코딩 형태를 반대로 바꿔 자동 1회 재시도
- `GET /trade/probe` — 키 형태(asIs/encoded/decoded/decodedThenEncoded)별 응답을 보여주는 진단 엔드포인트(키 값 자체는 노출하지 않고 길이·형태만 표시)

### 확인 방법
```bash
curl "https://jinga-korea-macro.tjtlswns95.workers.dev/trade/probe"   # 어떤 키 형태가 통하는지
curl "https://jinga-korea-macro.tjtlswns95.workers.dev/trade/apt"     # 실제 집계 결과
```
`/trade/apt`가 200으로 자치구별 데이터를 돌려주면, 사이트는 새로고침만 해도 지도·법정동 표가 실측치로 바뀝니다(프론트엔드 코드는 이미 반영 완료).

## 5. Worker별 메모

### jinga-yahoo-proxy (배포 완료)
- `POST /quotes` — `{symbols:[{type:'index'|'kr'|'us', code, market?}]}` → `{[code]:{price, change, changePct, source}}`
- `POST /history` — 1년치 일봉에서 최근 30거래일 종가 + YTD 수익률(1시간 캐시)
- 국내는 네이버 금융, 해외·환율은 야후. 네이버 실패 시 야후로 자동 대체
- ⚠️ **Cloudflare 무료 플랜은 요청당 외부 호출 50개 제한** — 프론트엔드가 심볼을 30개씩 나눠 호출합니다. 종목을 더 추가해도 이 로직 덕분에 안전합니다

### jinga-korea-macro (일부 변경분 미배포 — 4번 참고)
- `GET /rate/base` · `/housing/weekly` · `/rate/mortgage` · `/trade/apt` · `/trade/complexes` · `/trade/probe`
- `GET /trade/complexes?gu=강동구,송파구&months=3` — 선택 자치구 × 최근 1~3개월(이번 달 포함) 실거래를 단지·전용면적별로 묶어
  최근 거래가·거래일·층·기간 내 최저/최고·건수를 반환(페이지의 "단지 검색"이 "최근 거래가 ≤ 예산"으로 거름).
  무료 플랜 외부 호출 한도 때문에 자치구 수 × 개월 수 ≤ 45(3개월이면 15개 구)
- 필요한 Secret: `ECOS_API_KEY`, `REB_API_KEY`, `FSS_API_KEY`, `MOLIT_API_KEY` (4개 모두 등록되어 있음)
- 주담대는 금감원 API가 "현재 공시월"만 제공 → 12개월 추이 중 최신월만 실측, 과거 11개월은 참고추세

### jinga-policy-proxy (배포 완료)
- `GET /policy` — Google 뉴스 RSS 다중 키워드 검색 → 최근 30일 정리, 키 불필요

### jinga-realestate-proxy (미사용)
실거래가를 처음엔 별도 Worker로 만들었다가, 키가 `jinga-korea-macro`에 등록되어 있어 그쪽으로 통합했습니다. 현재 사이트는 이 Worker를 호출하지 않습니다. 정리하고 싶으면 Cloudflare 대시보드에서 삭제해도 무방하고, 그대로 둬도 과금·영향 없습니다.

## 6. 보안 원칙

- **API 키는 소스에 절대 넣지 않습니다.** 전부 Cloudflare Secret(`wrangler secret put`)으로만 관리합니다.
- 이 저장소 어디에도 키 값이 없습니다. `.dev.vars`(로컬 테스트용)는 `.gitignore` 처리되어 있습니다.
- Secret은 등록 후 대시보드에서도 다시 볼 수 없습니다(write-only). 분실 시 발급처에서 재발급해야 합니다.
