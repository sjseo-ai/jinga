# T009 — 데이터 사전

작성 2026-11-19 · 기계가 읽는 쪽은 `data/source-policy.json`
**아직 인증키가 승인되지 않아 실거래 응답을 한 번도 받아 보지 못했습니다.** 그래서 아래 필드표는
포털 문서에서 확인한 것과 **키가 열리면 실제 응답으로 확정할 것**을 나눠 적습니다.

## 1. 단지를 무엇으로 식별할 것인가 — 가장 먼저 풀 문제

지금 진가는 **KB 단지일련번호**를 열쇠로 씁니다. KB를 끊으려면 이 열쇠부터 바꿔야 합니다.

| 자료 | 단지 식별자 | 비고 |
|---|---|---|
| KB 단지목록 | `단지기본일련번호` | **버려야 할 열쇠** |
| K-apt | `kaptCode` | 이미 2,002장의 단지 페이지가 이것으로 만들어져 있음 |
| 실거래 API | **단지 코드가 없음** — `아파트`(이름) + `법정동` + `지번` + `건축년도` | 이름으로 맞춰야 함 |
| 건축물대장 | `시군구코드` + `법정동코드` + `번` + `지` | 지번이 열쇠 |

**그래서 핵심 작업은 「실거래의 `aptSeq` → K-apt `kaptCode`」 대응표를 만드는 일입니다.**
거래를 단지로 묶는 것은 `aptSeq` 로 해결되지만, 그 단지가 **우리 단지 페이지의 어느 단지인지**는
여전히 이름과 법정동으로 맞춰야 합니다.

### 측정 결과 (2026-11-19 · 서울 12개월 62,335건)

| | |
|---|---|
| 실거래에 나온 단지 | 5,821곳 |
| 우리가 가진 K-apt 단지 | 1,069곳(300세대 이상만) |
| **그중 가격을 붙일 수 있는 곳** | **799곳 = 74.7%** |
| 이름이 엇갈려 못 맞춘 곳 | 218곳 |
| 후보가 여럿이라 포기한 곳 | 52곳 |

어긋나는 유형은 세 가지였습니다 — 「상계주공7(고층)」↔「상계주공7단지」, 「에스케이북한산시티」↔「SK북한산시티아파트」,
「중계그린1단지」↔「중계그린」. 앞의 둘은 규칙으로 해결했고, 세 번째는 **후보가 하나일 때만** 허용합니다.
1차·2차가 따로 있는 단지에 그냥 붙이면 남의 단지 가격이 나갑니다.

**못 맞춘 단지는 가격을 보여 주지 않습니다.** 74.7%면 74.7%라고 적습니다.
나머지를 채우려고 규칙을 더 늘리는 것보다, K-apt 공식 단지 목록 API(15057332)로 색인을 넓히는 쪽이 맞습니다.

## 2. 실거래 매매 — 쓸 필드 (**2026-11-19 실제 응답으로 확정**)

인증키가 승인되어(2026-11-19) 실제 응답을 받았습니다. 상세 자료(15126468)에는 **`aptSeq`(단지 일련번호)**가
들어 있어, 거래를 단지별로 묶는 일은 이름을 맞출 필요 없이 해결됩니다.
아래는 2026-10 강동구 응답에서 직접 확인한 필드입니다.

| 필드 | 값 보기 | 쓰는 이유 |

> 포털 설명에 「개인정보 보호를 위해 층 정보만 제공되며, 소유권 이전등기 완료 건에 한해 동 정보가 추가 공개」라고

## 4. 저장할 메타데이터 (T010 과 연결)

어떤 값이든 **혼자 두지 않습니다.** 항상 다음을 같이 저장합니다.

```
원천키(source-policy.json 의 key) · 원천 기준일 · 수집 시각 · 수집 방법(API/파일) · 이용조건 확인일
```

이유는 두 가지입니다.
1. 「이 숫자 어디서 났냐」는 질문에 코드를 안 뒤져도 답할 수 있어야 합니다. 이번 KB 감사에서 그게 안 돼
   나흘이 걸렸습니다.
2. 유료 보고서를 팔려면 **숫자마다 출처와 기준일을 표시**해야 합니다(로드맵 hard_rules 5).

## 5. 확인하지 못한 것

- 세 실거래 API 모두 **일일 트래픽 한도가 페이지에 없습니다.** 활용신청 화면에서 확인해야 합니다.
- **K-apt API 의 이용허락범위를 원문으로 확인하지 못했습니다.** 사이트 공개 페이지 2,002장이 전부
  이 자료라 가장 먼저 확인할 항목입니다.
- 학교알리미·OpenTopoData 의 상업적 이용·재배포 조건.
