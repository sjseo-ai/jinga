# T002 — 데이터 계보·외부전송 감사

작성 2026-11-19 · 필드 단위 표는 `artifacts/source-register.csv` · 구성 현황은 `docs/current-state.md`. 진가의 화면에 나오는 값을 **원천별로 갈라 놓은 표**입니다.
목적은 하나입니다 — KB부동산에서 온 값과 저희가 공공데이터로 만든 값을 섞어 두지 않는 것.
섞여 있으면 「이 기능은 KB 없이 돌아가는가」를 매번 코드를 읽어 가며 답해야 합니다.

## 3. KB 없이도 도는 것 — 사이트의 대부분

- **단지 페이지 2,002장** — 전부 K-apt. 시세 한 줄도 없음.
- **자치구 페이지 33장** — 2026-11-19 부터 K-apt 만.
- 재건축·리모델링 조합, 경사도, 입지(지하철·학교), 취득세·중개보수 계산기.

## 3-1. 확인한 것과 추정인 것

로드맵 T002 는 둘을 섞지 말라고 요구합니다. 섞으면 변호사가 사실관계를 다시 파야 합니다.

**확인(코드·응답·배포로 직접 봄)**
- 서버 주간 작업이 KB 를 대량 조회해 비공개 Blob 에 저장했다 — `api/_job.mjs` 의 `kb` 단계와 `store.put` 경로
- 이용자 검색은 브라우저가 `api.kbland.kr` 을 직접 부른다 — `index.html` 의 `KB_API`
- 전수 엑셀·주간 메일 첨부·자치구 페이지 평당가·공개 보고서 사본은 **지금 운영 환경에 없다** — 배포 후 라이브 확인(평당 0건, 버튼 0건, `/r/…` 404)
- 국토부 실거래 인증키는 거부된다 — `403 SERVICE_KEY_IS_NOT_REGISTERED_ERROR`
- 로그인·차단 우회는 하지 않는다 — KB 호출에 자격증명이 없고, 헤더는 UA·Referer 뿐이며 우회 코드가 없다

**추정(법률 확인 필요 — Claude 가 단정하지 않음)**
- KB 시세의 데이터베이스제작자 권리 성립 여부와 「상당 부분」의 범위
- 이용자 브라우저가 직접 조회하는 방식이 약관상 「이용자의 이용」인지 「서비스의 수집」인지
- 집계 통계(`data-api.kbland.kr`) 조회가 단지별 조회와 같은 평가를 받는지
- 이미 저장된 Blob 조각의 보관·삭제가 증거보존 의무와 충돌하는지

## 4. 실거래로 옮겨야 하는 것

| 지금 KB가 채우는 값 | 실거래로 만들 값 | 필요한 작업 |
|---|---|---|
| 주택형별 일반거래가 | 최근 실거래 + 유사거래 보정 추정가 | 단지·면적별 거래 집계, 추정 모델 |
| 구·동 평당가 | 실거래 평당가 집계 | 거래 없는 달 처리 |
| 호가 | 없음 | 적법한 매물 데이터 확보 전까지 기능 제외 |
| — | **신뢰도 등급** | 거래가 드문 단지는 값 대신 범위와 등급 |

**지금 막힌 곳은 데이터 한 군데입니다.** `data.go.kr` 인증키가 「국토교통부_아파트 매매 실거래가 자료」에
승인되어 있지 않습니다(HTTP 403 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`).
활용신청이 승인되면 `workers/jinga-korea-macro` 의 `/trade/apt`·`/trade/complexes` 가 바로 응답합니다 —
호출부는 이미 만들어져 있고 테스트도 있습니다(`scripts/smoke-trades.mjs`).
