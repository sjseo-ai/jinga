# 대출·비용 계산 — 모델 카드 (T016)

만든 날 2026-11-23
코드 `scripts/_finance.mjs` · 규칙집 `data/finance-rules.json` · 테스트 `scripts/smoke-finance.mjs`(24건) · 실행 `npm run finance`

## 무엇을 하는가

**이 집을 사면 돈이 언제 얼마나 나가는지**를 계산합니다. 세 토막입니다.

| | 성격 | 내용 |
|---|---|---|
| 살 때 | 사실 | 취득세·지방교육세·농특세·중개보수·법무등기 |
| 빌릴 때 | 사실 | LTV·총액상한·DSR 중 **가장 작은 한도**, 상환 스케줄(원리금균등/원금균등/만기일시·거치) |
| 가질 때 | 사실 | 재산세·도시지역분·지방교육세·종부세·농특세·관리비 |
| 팔 때 | **가정** | 양도세·장특공제, 가격이 ±로 움직인다고 *쳤을 때*의 손익 |

## 가장 중요한 설계 원칙 세 가지

**1. 사실과 가정을 코드 수준에서 분리했습니다.**
`plan()` 은 매도가격을 *계산하지 않습니다.* 미래 가격이 필요한 계산은 전부 `scenarios()` 안에만 있고,
결과마다 `assumed: true` 가 붙습니다. 테스트가 `plan()` 출력에 `sellPrice`·`yearlyGrowth` 문자열이
**없다는 것**을 직접 확인합니다. 섞이면 테스트가 깨집니다.

**2. 세법 수치는 코드에 없습니다.** 전부 `data/finance-rules.json` 에 있고, 규칙마다 출처와 확신도가 붙습니다.

| 확신도 | 뜻 | 해당 규칙 |
|---|---|---|
| `confirmed` | 복수 출처 일치 + **외부 계산 예시로 대조 성공** | 취득세, 재산세 |
| `likely` | 복수 출처가 대체로 일치하나 법령 원문 미확인 | 중개보수, 종부세, 양도세 |
| `uncertain` | **출처마다 값이 엇갈림** | LTV·스트레스DSR, 다주택 중과(취득·양도), 생애최초 감면, 법무등기 실비 |

**3. 못 믿을 값은 숨기지 않고 경고로 같이 냅니다.**
`uncertain` 규칙이 실제로 쓰이면 결과의 `warnings[]` 에 **왜 못 믿는지**가 함께 담깁니다.
숫자를 안 내놓으면 쓸모가 없고, 경고 없이 내놓으면 거짓말이 되기 때문입니다.

## 대조검증한 값 (테스트에 박아 둔 것)

손으로 검산했거나 **외부 계산 예시와 맞아떨어진** 값만 테스트에 적었습니다.

| 항목 | 입력 | 결과 | 대조 근거 |
|---|---|---|---|
| 취득세 | 6억·85㎡ 이하 | 660만원 | 외부 예시와 일치 |
| 취득세 | 9억·85㎡ 초과 | 3,150만원 | 외부 예시와 일치 |
| 재산세 | 공시 3억 1주택 | 본세 99,000 · 도시 180,600 · 교육 19,800 = **299,400원** | 외부 예시와 **원 단위까지** 일치 |
| 월 상환액 | 3억·4%·30년 원리금균등 | 1,432,246원 | 금융 공식 + 널리 쓰이는 대조값(30만당 1,432.25) |
| 총이자 | 3억·4%·30년 만기일시 | 360,000,000원 | 닫힌 수식 `P×r×n` 과 일치 |
| 총이자 | 3억·4%·30년 원금균등 | 180,500,000원 | 닫힌 수식 `i×P×(n+1)/2` 와 일치 |
| 종부세 | 공시 15억 1주택 단독 | 본세 90만 + 농특세 18만 = 108만원 | 조문 손계산 |
| 양도세 | 10억→15억·5년 보유거주 | 804만 + 지방 80.4만 = **884.4만원** | 조문 손계산(고가주택 안분·장특 40%) |
| 양도세 | 8억→9억·1.5년 | 단기 60% 적용 5,850만원 | 「단기세율과 기본세율 중 큰 쪽」 |

## 알면서 비워 둔 것

이 값들은 **실제 고지액을 실제보다 높게** 잡습니다. 즉 이 계산은 보수적입니다.

- 재산세 **세부담상한제**(전년 대비 105~130%)
- 종부세 **재산세 중복분 공제**, **고령자·장기보유 세액공제**(합산 최대 80%)

그리고 아예 안 다루는 것:

- 임대소득·전세보증금 운용, 중도상환수수료, 변동금리 경로, 분양권·조합원입주권
- **다주택자** — 계산은 되지만 중과 규정이 불확실해 경고가 붙습니다. 권하지 않습니다.
- 공시가격을 모를 때는 **시세의 70%** 로 가정합니다(`publicPriceRatio`). 실제 공시가를 넣는 쪽이 정확합니다.

## 세법이 바뀌면 — 갱신 경로

1. `data/finance-rules.json` 의 해당 값을 고치고, `version`·`asOf` 를 그날로 올립니다.
2. 출처 링크와 `confidence` 를 함께 갱신합니다. 원문을 확인했으면 `confirmed` 로 올릴 수 있습니다.
3. `node --test scripts/smoke-finance.mjs` — 대조값이 깨지면 **고친 값이 틀렸거나 테스트가 낡은 것**입니다.
   둘 중 어느 쪽인지 확인하기 전에는 테스트를 고치지 마십시오.
4. 코드는 건드릴 필요가 없습니다. 구간표 모양이 바뀐 경우에만 `_finance.mjs` 를 봅니다.

**자동 알림:** 규칙집 기준일이 `staleAfterDays`(180일)를 넘기면 모든 계산 결과에
「규칙집이 묵었다」는 경고가 자동으로 붙습니다. 대표가 잊어도 결과지가 먼저 말합니다.

## 쓰는 법

```bash
npm run finance                                   # 기본 대표 시나리오
npm run finance -- --price 12 --cash 7 --income 1 --rate 4.0 --hold 5 --regulated
npm run finance -- --price 9 --area 101 --first-home --json
```

금액 단위는 **억원**, 금리는 **%**. `--principal`(원금균등) `--bullet`(만기일시) `--houses N` `--adjusted` 를 붙일 수 있습니다.

## 이 모델을 믿으면 안 되는 지점

- **세무·금융 자문이 아닙니다.** 신고·대출 전에 위택스·홈택스·취급 은행에서 확인해야 합니다.
- LTV와 스트레스 DSR은 조사한 출처마다 값이 달랐습니다. 대출 한도는 **방향만** 참고하십시오.
- 미래 손익은 **가정의 결과**입니다. 진가는 가격을 예측하지 않습니다.
