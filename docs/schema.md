# 실거래 자료 스키마와 갱신 규칙 (㉮ T010)

대상 파일 `data/trades-seoul.json` · 갱신 2026-11-26

이 문서는 **거래 한 건이 어떤 모양인지**와 **파일을 어떻게 갱신하는지**를 적습니다.
숫자의 단위와 「없음」의 뜻을 틀리면 조용히 10배가 어긋나므로, 그 두 가지를 가장 먼저 적었습니다.

## 어디서 오는가

| | |
|---|---|
원천 | 국토교통부_아파트 매매 실거래가 **상세** 자료
식별자 | 공공데이터포털 `15126468` · `RTMSDataSvcAptTradeDev`
이용허락 | **제한 없음**
인증키 | `.secrets/molit.json` (git 제외). 화면·로그·파일에 키를 쓰지 않습니다
조회 단위 | 자치구(`LAWD_CD`) × 한 달(`DEAL_YMD`) — 한 번에 한 칸씩
쪽 나눔 | `pageNo`/`numOfRows=1000`, `totalCount` 를 보고 끝까지 받습니다

**왜 「상세」 쪽인가** — 쪽 나눠 받기가 되고, **`aptSeq`(단지 일련번호)** 가 들어 있습니다.
`aptSeq` 가 없으면 같은 단지를 묶을 열쇠가 이름뿐이고, 이름은 믿을 수 없습니다.

## 거래 한 건 (`trades[]`)

정규화는 `scripts/_trades.mjs` 의 `toTrade()` 가 합니다. 네트워크도 파일도 건드리지 않는 순수 함수입니다.

| 칸 | 자료형 | 뜻 | 원천 필드 |
|---|---|---|---|
`seq` | 문자열 \| null | **단지 일련번호** — 같은 단지를 묶는 열쇠 (`11740-2609`) | `aptSeq`
`name` | 문자열 | 단지명 (`늘푸른아파트`) | `aptNm`
`gu` | 문자열 | 자치구 — 조회할 때 우리가 넣는 값이고 응답에는 없습니다 | (조회 조건)
`dong` | 문자열 | 법정동 (`천호동`) | `umdNm`
`jibun` | 문자열 | 지번 (`52-16`) | `jibun`
`sggCd` | 문자열 | 시군구 코드 (`11740`) | `sggCd`
`date` | `YYYY-MM-DD` | 계약일. 일자가 없으면 1일로 채웁니다 | `dealYear/Month/Day`
`amount` | 정수 | **금액(만원)** — 아래 단위 항목을 꼭 보십시오 | `dealAmount`
`area` | 수 | 전용면적(㎡), 소수 둘째 자리 | `excluUseAr`
`perPyeong` | 정수 \| null | 평당가(만원) = `amount ÷ (area ÷ 3.3058)` | (계산)
`floor` | 정수 \| null | 층 | `floor`
`year` | 정수 \| null | 준공연도 | `buildYear`
`kind` | 문자열 \| null | `중개거래` \| `직거래` | `dealingGbn`

### 단위 — 여기서 틀리면 10배가 어긋납니다

`amount` 와 `perPyeong` 은 **만원**입니다. 원이 아닙니다. API 가 만원으로 주고, 우리는 **바꾸지 않습니다.**
화면에 「11억 6,190만원」으로 보일 때 파일에 든 값은 `116190` 입니다.
원 단위로 바꾸는 곳은 화면·보고서뿐이고, 자료 파일에서는 끝까지 만원입니다.

### `null` 은 0이 아닙니다

`floor: null` 은 「1층」이 아니라 **「층을 모름」** 입니다. `Number(null)` 이 `0` 이 되는 바람에
「모르는 거리」가 「0m = 만점」으로 채점된 일이 실제로 있었습니다(`jinga-reco.mjs` 의 `hasNum()`).
이 파일을 읽는 코드는 `null` 을 숫자로 바꾸기 전에 반드시 걸러야 합니다.

### 빠지는 건 — 무엇이 왜 빠졌는지 셉니다

| 빠지는 까닭 | 어떻게 | 어디에 세는가 |
|---|---|---|
**해제(취소)된 거래** | `cdealType` 에 「해제」가 있거나 `cdealDay` 에 날짜가 있으면 뺍니다 | `stats[].cancelled`
금액·면적·날짜가 없거나 0 | 쓸 수 없으니 뺍니다 | `stats[].broken`

**해제를 빼지 않으면 허위 고가가 평균에 그대로 들어갑니다.** 2026-02 에 신고하고 2026-03 에
해제한 건은 **2026-02 응답에 해제 표시가 붙어 다시 나옵니다** — 이 성질이 아래 갱신 규칙을 정합니다.

## 파일 전체 모양

```
{
  generatedAt : ISO 시각 — 마지막으로 이 파일을 쓴 때
  source      : 원천 이름과 이용허락 한 줄
  months      : ["202611", "202610", …]  최근 달이 앞 (build-trade-prices 가 months[0] 을 기준월로 씁니다)
  gus         : ["강남구", …]            자치구명 가나다순
  counts      : { trades, complexes, cancelled, failedQueries }
  stats       : [ 자치구 × 달 한 칸마다 한 줄 ]   ← 아래
  refresh     : { lastRunAt, window, history[] }  ← 아래
  trades      : [ 거래 ]                 자치구 → 날짜 → 단지 → 금액 → 면적 → 층 순
}
```

`trades` 를 **정해진 순서로 정렬해 쓰는 이유** — 같은 자료를 두 번 쓰면 같은 파일이 나와야
무엇이 바뀌었는지 볼 수 있습니다. 읽는 쪽은 순서에 의존하지 않습니다(모두 묶거나 걸러 씁니다).

### `stats[]` — 0건과 모름을 가르는 칸

```
{ gu, ym, ok: true,  total, kept, cancelled, broken, fetchedAt? }
{ gu, ym, ok: false, error }
```

**`stats` 는 언제나 `trades` 에 실제로 든 것을 설명합니다.** 거래가 0건인 달(`ok:true, kept:0`)과
조회가 막힌 달(`ok:false`)을 같이 적으면 「이 동네는 거래가 없다」는 거짓말이 됩니다.
그래서 달마다 한 줄을 남기고, 갱신에 실패한 조회는 **`stats` 를 덮지 않고** 따로 보고합니다
(아래 「실패한 달」 항목).

### `refresh` — 갱신 이력

```
{ lastRunAt, window, history: [ { at, window, gus, cells, added, removed, same, failed }, … ] }
```

최근 **30회**만 남깁니다(`HISTORY_KEEP`). 파일이 이력으로 부풀면 안 됩니다.
`history[0].at` 이 오래되었으면 자료가 묵은 것입니다.

## 갱신 — 두 가지 방식

| | 전체 수집 | 일별 갱신 |
|---|---|---|
명령 | `npm run trades:seoul` | `npm run trades:refresh` |
스크립트 | `scripts/build-trades.mjs` | `scripts/refresh-trades.mjs` |
조회 수 | 25개구 × 12개월 = **300회** | 25개구 × 3개월 = **75회** |
걸리는 시간 | 몇 분 | **20여 초** (2026-11-26 실측 22초) |
하는 일 | 파일을 새로 만듭니다 | 최근 몇 달만 갈아 끼웁니다 |
언제 | 달에 한 번, 또는 처음 | 하루 한 번 |

### 다시 받은 달은 **통째로** 교체합니다

새로 들어온 건만 더하는 방식이면, 그동안 **해제된 건이 우리 파일에 영원히 남아** 허위 고가로
평균을 올립니다(해제는 원래 달의 응답에 표시가 붙어 나오므로, 「새 건」으로는 절대 안 들어옵니다).
그래서 다시 받은 칸(자치구 × 달)의 기존 거래는 **버리고 새로 깝니다.**

2026-11-26 첫 갱신에서 **사라진 12건** — 그게 바로 남겨 두면 안 되는 건들입니다.

### 실패한 달은 **손대지 않습니다**

조회가 실패하면 그 칸은 이전 자료를 그대로 둡니다. 실패를 0건으로 치면 API 가 한 번 흔들릴 때마다
멀쩡한 한 달이 지워집니다. 실패는 `stats` 를 덮지 않고 실행 보고와 `refresh.history[].failed` 에만 적습니다.

### 이 갱신이 **못 잡는 것**

**갱신 창(기본 3개월) 밖에서 해제된 건은 사라지지 않습니다.**
2026-03 거래가 2026-11 에 해제되면, 3개월 창은 2026-03 을 다시 받지 않으므로 그 건이 남습니다.

→ **한 달에 한 번은 `npm run trades:seoul` 로 전체를 다시 받으십시오.**
→ 급하면 창을 넓히십시오: `node scripts/refresh-trades.mjs --months=12`

기본 창을 3개월로 둔 까닭은 **신고 기한이 계약일로부터 30일**이어서, 두 달 전 계약이 이번 달에
들어오는 일이 흔하기 때문입니다. 3개월이면 그 지연을 감쌉니다.

### 창을 넓히는 비용

창 1개월당 조회 25회가 늘어납니다. `--months=12` 는 전체 수집과 같은 300회이지만,
**실패한 달을 지우지 않는다**는 점에서 전체 수집과 다릅니다.

## 반드시 지키는 것 셋

### ① 전세와 월세를 섞지 않습니다

`monthly === 0` 이면 전세, `0` 보다 크면 월세입니다. **반전세(보증금 크고 월세 조금)도 월세로 봅니다.**
월세의 보증금(2.5억)을 전세 보증금과 같이 평균하면 전세 시세가 반 토막으로 나옵니다.

서울 12개월 실측 — **전세 112,077건 · 월세 115,712건.** 거의 반반이라 섞으면 크게 틀립니다.

### ② 갱신 계약을 시세로 쓰지 않습니다

갱신은 **전월세상한제(5%)** 에 묶여 시세보다 낮습니다. 실측으로 확인했습니다 —
표본 3,290건에서 전세 보증금 중앙값이 **신규 65,000 · 갱신 57,000만원(12% 차이)** 입니다.

서울 12개월에서 전세 112,077건 중 **갱신이 56,488건 — 절반이 넘습니다.**
섞으면 전세가율이 그만큼 낮게 나옵니다. 그래서 시세는 **신규 전세만**(`isMarketJeonse`) 씁니다.
쓰지 않은 갱신·월세 건수는 **버리지 않고 함께 셉니다**(`renew`·`wolse`) — 몇 건 중 몇 건을 썼는지 보여야 따질 수 있습니다.

### ③ 면적은 반올림해 짝을 맞춥니다

전월세는 `59.785` 처럼 **소수 셋째 자리까지** 옵니다. 매매 집계(`mainAreas`)가 반올림한 정수로 묶으므로
같은 반올림(`areaKey`)을 써야 짝이 맞습니다. 원값은 `area` 에 그대로 남깁니다.

> 처음에 강동구 한 달만 보고 「면적이 정수로 온다」고 적을 뻔했습니다 — 마침 올림픽파크포레온이
> 49·84㎡ 딱 떨어지는 신축이었습니다. 네 구·네 달로 넓혀 보니 3,290건 중 3,195건에 소수가 있었습니다.

## 매매와 다른 점 — 해제 칸이 없습니다

이 API 응답에는 `cdealType`·`cdealDay` 가 **아예 들어오지 않습니다**(2026-11-26 확인).
그래서 매매처럼 「해제된 건을 빼는」 일은 없습니다. 다만 늦은 신고·수정은 있으므로
**갱신할 때 달을 통째로 갈아 끼우는 규칙은 그대로** 지킵니다. 합치기 규칙 자체는
`_trades.mjs` 의 `mergeRefresh` 를 그대로 쓰고, **열쇠만** 전월세용으로 바꿉니다(`rentKey`) —
보증금이 같고 월세만 달라도 다른 계약이므로 **둘 다** 열쇠에 들어갑니다.

## 전세가율

```
전세가율 = 신규 전세 보증금 중앙값 ÷ 매매 추정가
```

| 지키는 것 | 어떻게 |
|---|---|
**분모가 추정치입니다** | 실거래가가 아니라 J-AVM 추정값입니다. 그래서 전세가율도 **추정**이고, 보고서에 「추정」 배지로 나갑니다 |
**표본이 적으면 안 냅니다** | 면적 칸당 신규 전세 `MIN_N`(3)건 미만이면 비웁니다. 한 건으로 단지 전세 시세를 말할 수 없습니다 |
**모르면 `null`** | 0 이 아닙니다. 0% 로 적으면 「전세가 공짜」가 됩니다 |
**단위가 어긋나면 버립니다** | 10%~100% 밖이면 버리고 **왜 버렸는지 함께** 남깁니다(`dropped`). 한쪽을 원으로 넣으면 100배가 어긋납니다 |

### 읽을 때 주의 — 낮은 전세가율이 「싸다」는 뜻이 아닙니다

**재건축 기대가 매매가에만 실린 단지에서 낮게 나옵니다.** 전세는 지금 사는 건물의 값이고,
매매가는 앞으로 지을 건물까지 보고 있기 때문입니다.

실제 값 — 은마 **24.8%** · 압구정미성2차 **21.6%** · 수서신동아 **26~29%**.
모두 재건축 기대 단지입니다. 이걸 「전세가 싸다」로 읽으면 거꾸로 해석하는 것이고,
보고서에도 그 주의를 주장 안에 적어 둡니다.

## 돌리는 순서

```
npm run rents:seoul       data/rents-seoul.json            전체 수집 300회 · 167초
npm run rents:refresh     같은 파일                         최근 3개월만 75회
npm run rents:prices      site/public/rent-price-seoul.json 전세 시세·전세가율
npm run build:decision    site/public/decision-index.json   화면·보고서용 색인에 전세가율 실음
```

매매(`trades:prices`)를 먼저 돌려야 분모가 생깁니다. 전세 파일이 없으면 `build:decision` 은
**전세가율 없이 그냥 넘어갑니다** — 빌드를 세우지 않습니다.

## 아직 안 한 것

- **월세는 전세가율에 쓰지 않습니다.** 전월세전환율(월세 ↔ 전세 환산)은 다음 판입니다.
- 전세가율의 **시간 변화**(작년 대비)는 아직 내지 않습니다. 달별 집계가 필요합니다.
- 갱신 건의 `preDeposit` 으로 **갱신 때 얼마나 올랐나**를 낼 수 있는데 아직 안 했습니다.
