# T014 — 개인정보 점검표

점검일 2026-11-20 · 점검 방법은 **코드를 열어 확인**(문서·기억이 아니라) · 자동 확인은 `scripts/smoke-privacy.mjs`

## 2. 고지문이 사실인지 — 검산 결과

| 고지문이 말하는 것 | 확인 결과 |
|---|---|
| 방문 집계에 **IP·User-Agent 를 저장하지 않는다** | ✔ `_stats.mjs` 가 담는 값은 `day · ref · utm · device · area` 뿐 |
| 남용 방지는 **해시로만** 센다 | ✔ `idKey()` = sha256(종류\|값\|소금) 앞 16자 · 원문 저장 없음 |
| 커뮤니티는 메일을 **알아볼 수 없게** 둔다 | ✔ `memberId()` = sha256(메일\|소금) 앞 24자 · 표시 이름은 앞 두 글자+별표 |
| 7일 안에 확인하지 않은 신청은 자동 삭제 | ✔ `dailyMaintenance()` 가 매일 지움 |
| 모든 메일에 수신 거부 링크 | ✔ `_mail.mjs linksFor()` — 토큰 없이는 해지되지 않음 |
| 보고서는 최근 8주만 보관 | ✔ `KEEP_WEEKS = 8` |

**고지문과 코드가 어긋나는 곳은 찾지 못했습니다.** (2026-11-20 기준)

## 3. 접근 통제

- 관리자 비밀번호는 **scrypt 해시만** 저장(N=16384, r=8, p=1) — 원문 없음
- 세션: HttpOnly 쿠키 12시간, 서명 키 = `JINGA_ADMIN_SECRET` + 비밀번호 기록 → **비밀번호를 바꾸면 모든 세션이 풀림**
- 무차별 대입: 같은 IP 15분에 5번 틀리면 15분 잠금, 전체 합쳐 30번이면 전체 잠금
- 운영 스크립트는 `Authorization: Bearer JINGA_ADMIN_SECRET`
- 메일을 보내는 공개 길목(구독 신청·커뮤니티 확인)은 속도 제한 적용

## 4. 비밀값

- 실제 값은 `.secrets/`(git 제외)와 Vercel·Cloudflare 환경변수에만 — 소스에 없음
- 배포 폴더(`site/public`)를 훑어 **키 모양 문자열 0건** 확인(2026-11-20)
- 서버 코드의 `console` 호출은 **전부 오류 메시지(e.message)** 뿐 — 우리가 메일 주소를 찍는 자리는 없음
- 다만 **메일 서버가 돌려주는 오류에는 받는 사람 주소가 섞여 옵니다**(예: `550 5.1.1 <someone@example.com> User unknown`).
  그대로 넘기면 Vercel 함수 로그에 남으므로, 메일 실패 로그는 `scrub()`(`api/_core.mjs`)로 **주소만 지우고** 남깁니다
- 인벤토리에는 환경변수 **이름만** 싣습니다(`artifacts/inventory.json`)

## 5. 이번 점검에서 고친 것

- **잠금 기록의 IP 원문** — `admin/login-guard.json` 이 접속 주소를 **열쇠 이름 그대로** 들고 있었습니다.
  고지문에는 「접속 주소는 해시값으로」라고 적어 두었으므로 **고지문이 맞고 코드가 틀린** 경우였습니다.
  `ipKey()`(sha256 + 관리 키 소금, 앞 16자)로 바꿨고, 테스트가 원문이 남는지 확인합니다.

- **nodemailer 10.0.9 → 10.6.0** — 주소 파서 결함 7건(moderate). 그중 하나는
  「따옴표 안의 `>` 가 주소를 일찍 끝내 **헤더에 없는 도메인으로 메일이 가는**」 것이라,
  구독자에게 메일을 보내는 이 서비스에 그대로 해당했습니다. 운영 의존성 `npm audit` 0건으로 정리.
- **메일 실패 로그 가림(`scrub()`)** — 위 4절 참고. 점검 중에 새로 만든 구멍막이입니다.
